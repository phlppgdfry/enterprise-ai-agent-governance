# One client, three complementary cases

Noordwerk is a fictional 140-person technical services company. All people, requests,
volumes, workshop findings and economics are synthetic. There is no real client engagement.

| Stage | Repository | Reviewer question |
|---|---|---|
| Decide | [Consulting Playbook](https://github.com/phlppgdfry/ai-transformation-consulting-playbook) | Is this worth doing, and under which conditions? |
| Deliver | [Automation Hub](https://github.com/phlppgdfry/enterprise-ai-automation-hub) | Can an employee request reach an accountable human decision? |
| Govern | [Agent Governance](https://github.com/phlppgdfry/enterprise-ai-agent-governance) | Can a policy assistant use approved sources without gaining decision authority? |

Operations owns materials, Finance expenses, IT access. Requests above €250 route to
Finance; access always routes to IT at €0. Every request awaits a person. Production
would require distinct queue permissions; the local approver covers all queues.

The proposed Microsoft landscape is a target architecture, not a deployed Noordwerk
solution. Existing Brevan and construction labs remain separate evidence with separate
fictional clients. No private lab artifact is republished here.
